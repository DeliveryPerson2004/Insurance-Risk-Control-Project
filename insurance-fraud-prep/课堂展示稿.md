# 医保欺诈检测 —— 数据预处理全流程展示

---

## 一、开场：为什么做这件事

大家好，今天我来给大家讲一下我们的项目——**医保欺诈检测的数据预处理流程**。

先说说背景。医保欺诈是目前医疗保险领域一个非常严重的问题。简单来说，就是有人通过虚假手段骗取医保基金。这个事情影响很大——它直接导致医保资金流失，损害的是我们每个人的切身利益。

那我们做的事情是什么呢？**从数据层面出发，对医保理赔数据进行预处理，构建欺诈标签，最终筛选出最有价值的特征，为后续建模打好基础。** 我们的输出是一个"拿来就能用"的建模数据集。

一句话概括我们的思路：**原始数据 → 清洗 → 标签构造 → 特征工程 → 特征选择 → 建模数据。**

---

## 二、数据概况：我们拿到了什么

我们的数据来源是两份医保理赔的 Excel 文件，每份都有 108 个字段。

- 第一份文件：41,692 条记录
- 第二份文件：35,219 条记录

合并去重之后，一共有 **76,911 条理赔记录**。

这些字段包含了理赔的方方面面：金额信息、诊断信息、医院信息、保单信息、被保险人信息、时间信息，以及理赔状态和拒赔原因等等。原始数据一共有 108 列，但并不是每一列都对我们的建模有用，所以第一步就是要"做减法"。

---

## 三、字段筛选：为什么只留 47 列

108 列里面，很多字段其实跟欺诈检测没什么关系。比如付款人姓名、银行账号、更新时间、系统内部 ID 等等——这些要么是纯管理字段，要么是隐私信息，对我们判断"这单是不是欺诈"没有帮助。

我们按照业务逻辑，把字段分成了 **8 大类**：

| 类别 | 示例字段 | 数量 |
|------|---------|------|
| 理赔金额 | 申请金额、拒赔金额、总收据金额 | 7 |
| 付款结构 | 社保支付、自费比例、免赔额 | 6 |
| 诊断信息 | 诊断编码、疾病大类 | 5 |
| 医院信息 | 医院等级、医院编码 | 4 |
| 理赔状态 | 理赔行状态、理赔单状态、拒赔码列表 | 3 |
| 被保险人 | 会员编号、会员类型、投保年数 | 3 |
| 保单信息 | 保单号、保障计划描述 | 5 |
| 时间特征 | 就诊起止日期、支付日期 | 5 |
| 其他特征 | 险种编码、发票数、每日限额等 | 7 |
| 行/单据信息 | 理赔号、行号 | 2 |

筛完之后，从 108 列变成 47 列。**少了一半还多，但每留下来的都是有业务意义的。**

---

## 四、数据清洗：把"脏数据"洗干净

原始数据有各种各样的问题，我们需要逐步处理。

### 4.1 金额列：去掉"RMB"，变成纯数字

原始数据里的金额字段，很多是带"RMB"前缀的字符串，比如"RMB 1,234.56"。这对计算机来说就是一串字符，没法做数学运算。

我们写了一个 `clean_currency` 函数：去掉"RMB"、去掉逗号、去掉空格，然后转成数值类型。这一步看着简单，但如果不做，后面所有的数值计算都跑不了。

### 4.2 日期列：从字符串变成可计算的数值

日期字段原来是"2023-01-15"这样的字符串格式。我们先用 `pd.to_datetime` 转成标准日期格式，然后从中**衍生出一个新特征**：`DAYS_FROM_INCUR_TO_PAY`，就是从就诊日期到支付日期之间的天数。

为什么要做这个？直觉上，**理赔处理时间的长短可能跟欺诈有关**——正常理赔一般有个合理的时间范围，而欺诈案件可能存在异常的处理周期。

### 4.3 类别列：统一大小写，清理脏值

类别字段的问题是不统一——同样是"省级"，有的写"省级"，有的写"省级"，有的带空格，有的全是大写。我们统一做了 `.str.strip().str.upper()` 处理，保证同一个含义的数据只有一种写法。

### 4.4 特殊字段：百分比、计数转数值

`COPAY_PCT`（自付比例）、`NO_OF_YR`（投保年数）、`POLICY_CNT`（保单数）这些字段，原始数据可能是字符串格式，我们强制转成数值。

---

## 五、缺失值和异常值处理

### 5.1 缺失值分析

我们先看了一下各个字段的缺失情况：

- `FILE_CLOSE_DATE` 缺失 63.5% —— 直接删掉，太多缺失值填了也不可信
- `BEN_HEAD_TYPE` 缺失 34.9% —— 保留，后面用众数填充
- `PAY_DATE` 缺失 17.2% —— 保留
- 还有一些缺失不到 1% 的字段——问题不大

**我们的策略是：缺失率超过 60% 的列直接删除，其余的做填充处理。** 为什么是 60%？这是一个经验值——缺失太多的字段，就算填了值，信息量也很低，反而可能引入噪声。

另外还发现了一个常量列 `CL_THIRD_PARTY_PAY_AMT`，方差为 0，也就是所有值都一样——这种字段对区分欺诈和非欺诈没有任何帮助，直接删掉。

### 5.2 缺失值填充

填充策略按数据类型不同而不同：

- **数值型**：用中位数填充。为什么不用均值？因为我们的数据里有很多金额字段，分布是右偏的（少数金额特别大），均值会被极端值拉高，中位数更稳健。
- **类别型**：用众数填充。先清理掉"NAN"、"NONE"这些脏标记，然后取该列出现次数最多的值来填。
- **日期型**：先转换为"距1970年1月1日的天数"（时间戳），变成数值后就能用中位数填充了。

最后我们还有一步"最终防线"——再跑一遍中位数填充，确保没有任何遗漏。**处理完之后，缺失值总数为 0。**

### 5.3 异常值处理：Winsorize

对于金额类的连续特征，我们用了 **1%-99% 分位数截尾（Winsorize）**。简单说就是：低于 1% 分位数的值，拉到 1% 分位数；高于 99% 分位数的值，压到 99% 分位数。

为什么用截尾而不是直接删掉？因为删掉异常值会减少样本量，而且有些"看起来异常"的值可能本身就是欺诈案件，删掉就丢信息了。截尾保留了这些记录，只是把极端值"拉回来"，让它不至于对模型造成过大影响。

注意我们排除了几个字段不截尾：`COPAY_PCT`、`NO_OF_YR` 这些本身取值范围就小的字段，以及分箱列。

## 六、标签构造：怎么定义"欺诈"

这是整个项目中**最核心的一步**——我们怎么判断一条理赔记录是不是欺诈？

### 6.1 业务逻辑

我们基于两个信号来定义欺诈：

1. **拒赔码包含 R530 或 T180**：这是业务系统中标识欺诈相关拒赔的专用代码
2. **实际支付金额为零**：说明这笔理赔最终没有被支付

**同时满足这两个条件的，我们标记为欺诈（FRAUD=1）。**

具体做法：
- 从 `RJ_CODE_LIST`（拒赔码列表）字段中用字符串匹配提取 `HAS_R530` 和 `HAS_T180` 两个辅助特征
- 定义 `IS_ZERO_PAY`：支付金额为零或者拒赔金额为负数（负数在系统中代表扣减）
- 最终标签：`FRAUD = (HAS_R530 == 1 | HAS_T180 == 1) & IS_ZERO_PAY == 1`

### 6.2 标签分布

结果显示，FRAUD=1 的有 56,267 条（约 73%），FRAUD=0 的有 20,644 条（约 27%）。

这个比例说明：**我们定义的"欺诈"占比偏高**。这在医保场景下是合理的——带有拒赔码且零支付的理赔确实占了相当大的比例。但也提醒我们，后续建模时需要注意类别不平衡的处理。

### 6.3 防止数据泄露

这里有一个**特别重要的设计决策**：在构造完标签之后，我们**立即删除了 `RJ_CODE_LIST` 和 `CODES` 这两个字段**。

为什么？因为欺诈标签就是从这两个字段里提取出来的。如果我们不删掉它们，模型训练的时候就会"看到答案"——直接从拒赔码字段读出欺诈标记，而不是从其他特征中去学习欺诈的模式。这叫**数据泄露（Data Leakage）**，会导致模型在训练集上表现极好，但到了真实数据上完全不work。

所以我们必须在标签构造完成后**第一时间删掉这两个泄露列**。

---

## 七、特征工程：让数据更适合建模

### 7.1 分箱处理

金额字段（如 `SUB_AMT`、`PAY_AMT_USD`）是连续数值，但对欺诈检测来说，我们更关心的是"这笔理赔的金额处于什么档次"，而不是具体的金额数字。

所以我们用 **5 分位分箱**，把金额变成 0-4 的离散等级（类似"很低、低、中等、高、很高"）。分箱之后，原始金额列就被替换掉了。

**注意分箱的时机**——我们在对数变换之前做分箱，因为分箱是基于原始金额的分布来划分的，如果先做了对数变换，分箱的结果就会不一样。

### 7.2 对数变换

很多金额字段的分布是严重右偏的——大部分理赔金额很小，但偶尔有几笔金额特别大。这种偏度会影响很多模型的性能。

我们对**偏度大于 1 的连续特征**做了 `log1p` 变换（即 log(1+x)）。这个变换可以把右偏分布拉得更对称，让模型更容易学习。

一共有 11 个特征接受了对数变换，包括各种金额字段和处理天数。

如果某个特征存在零值或负值，我们会先做一个平移（减去最小值再加 1），保证对数运算的有效性。

### 7.3 标准化

标准化（StandardScaler）就是把所有数值特征变成均值为 0、标准差为 1 的分布。

这一步的目的：不同字段的量纲差异很大——金额可能是几万、几十万，而投保年数可能就是个位数。如果不标准化，量纲大的字段会主导模型训练。标准化之后，所有特征站在同一起跑线上。

注意：标签列 `FRAUD`、辅助特征 `HAS_R530`/`HAS_T180`/`IS_ZERO_PAY`、以及分箱列不做标准化——它们要么是 0/1 的标签，要么已经是离散等级，标准化没有意义。

### 7.4 类别编码

剩下的类别字段（如诊断编码、保障计划描述、险种编码等）需要变成数值才能被模型处理。

我们用了 **Label Encoding**——给每个类别的字符串分配一个整数编码。比如保障计划描述有"基础版""升级版""高端版"，就编码成 0、1、2。

需要注意的是，Label Encoding 会给类别赋予一个"顺序"关系（0 < 1 < 2），但实际上这些类别之间可能没有大小关系。后续的特征选择阶段，我们用了随机森林而非线性模型来缓解这个问题。

---

## 八、特征选择：从 37 个特征中选出最好的 10 个

经过前面的处理，我们有 47 列。去掉 9 个 ID 列（理赔号、会员号等——这些是标识符，不具备预测能力），再去掉标签列，剩下 **37 个候选特征**。

但 37 个特征对建模来说还是偏多的——特征太多会导致模型复杂度过高，容易过拟合。所以我们用了**三步走的特征选择策略**：

### 8.1 第一步：过滤法（Filter）

过滤法是最简单直接的方式，不依赖任何模型，纯粹基于数据本身的统计特性。

- **低方差过滤**：方差小于 0.01 的特征去掉。直觉是：如果一个特征在所有样本上的取值几乎不变，那它对区分欺诈和非欺诈就没用。这一步从 37 个特征去掉了 2 个，剩 35 个。
- **单变量相关性过滤（SelectKBest）**：用 F 检验计算每个特征和标签之间的相关性，选出最相关的 20 个。这一步从 35 个去掉 15 个，剩 20 个。

### 8.2 第二步：嵌入法（Embedded）

嵌入法是"训练一个模型，让它告诉我们哪些特征重要"。

我们训练了一个 **100 棵树的随机森林**，让它计算每个特征的重要性（基于基尼不纯度的减少量）。结果发现：

| 特征 | 重要性 |
|------|--------|
| IS_ZERO_PAY | 0.2808 |
| REJECTED_AMT | 0.2071 |
| COPAY_PCT | 0.1839 |
| HAS_R530 | 0.1423 |
| HAS_T180 | 0.0492 |
| KIND_CODE | 0.0185 |
| APP_AMT | 0.0180 |
| PROV_LEVEL | 0.0169 |
| POCY_PLAN_DESC | 0.0138 |
| CWF_AMT_DAY | 0.0133 |

**前四个特征就占了超过 80% 的重要性**——零支付、拒赔金额、自付比例、拒赔码。这和我们的标签定义是吻合的，说明这些特征确实和欺诈高度相关。

然后用 `SelectFromModel` 以中位数为阈值筛选，保留了 10 个特征。

### 8.3 第三步：包装法（Wrapper）

包装法的想法是"用模型实际跑一遍，看去掉哪个特征模型表现下降最多"。但因为我们嵌入法之后只剩下 10 个特征了，已经达到目标数量，所以**包装法这一步被跳过了**。

> 如果嵌入法之后保留的特征多于 10 个，我们会用 RFE（递归特征消除）进一步筛选。

### 8.4 最终特征列表

最终我们保留了 10 个特征 + 1 个标签：

| 特征 | 业务含义 |
|------|---------|
| APP_AMT | 申请金额 |
| REJECTED_AMT | 拒赔金额 |
| COPAY_PCT | 自付比例 |
| PROV_LEVEL | 医院等级 |
| POCY_PLAN_DESC | 保障计划描述 |
| KIND_CODE | 险种编码 |
| CWF_AMT_DAY | 每日限额 |
| HAS_R530 | 是否含R530拒赔码 |
| HAS_T180 | 是否含T180拒赔码 |
| IS_ZERO_PAY | 是否零支付 |
| **FRAUD** | **欺诈标签（目标变量）** |

我们最终输出了两个文件：

| 文件 | 形状 | 说明 |

## 十、关键设计决策总结

回顾整个流程，我觉得有几个决策点值得强调：

1. **标签定义的选择**：我们用了业务系统已有的拒赔码（R530/T180）结合零支付来定义欺诈。这是一个"有监督"的标签构建方式——依赖于业务系统的标注。如果业务系统本身对欺诈的标注不准确，那我们的标签也会有问题。

2. **数据泄露的防范**：在构造完标签后立即删除原始拒赔码字段。这一步如果遗漏，整个项目的结论就不可信了。

3. **特征工程的顺序**：分箱 → 对数变换 → 标准化 → 标签编码。这个顺序是有讲究的——分箱基于原始金额分布，对数变换消除偏度，标准化统一量纲，最后编码类别变量。

4. **特征选择的三层筛选**：过滤 → 嵌入 → 包装，从粗到细逐步筛选。这种方法比单一方法更稳健——过滤法快速去噪，嵌入法利用模型能力筛选，包装法做最终精调。

5. **73% 的正样本比例**：这个比例偏高，说明我们的欺诈定义可能"太宽"了。在后续建模中，可以考虑调整标签定义，或者使用过采样/欠采样等技术来平衡类别。

---

## 十一、不足与改进方向

坦白说，这个预处理流程还有一些可以改进的地方：

1. **标签定义过于简单**：仅基于拒赔码和零支付来判断欺诈，可能会漏掉很多隐蔽的欺诈手法（比如过度医疗、虚假诊断等），也会把一些正常但被拒赔的案例错误标记为欺诈。

2. **没有做交叉验证**：特征选择阶段用的是全量数据，没有留出验证集。如果后续建模时发现效果不好，可能需要回头调整特征选择策略。

3. **类别编码方式简单**：Label Encoding 对高基数类别（比如诊断编码有几百个不同的值）可能不是最佳选择，可以考虑 Target Encoding 或 Frequency Encoding。

4. **缺乏探索性数据分析（EDA）**：我们直接进入预处理流程，没有先对数据做充分的可视化和探索。如果先做 EDA，可能会发现更多有价值的洞察。

---

## 十二、总结

总的来说，我们做的事情就是把一份"原始的、杂乱的"医保理赔数据，通过一系列标准化的处理步骤，变成了一份"干净的、可直接建模的"数据集。

整个流程的核心逻辑是：**理解业务 → 清洗数据 → 构造标签 → 工程特征 → 筛选特征 → 输出数据。** 每一步都是在回答一个问题——"这个数据里，哪些信息对判断欺诈最有价值？"

这就是我们项目的全部内容。谢谢大家！
